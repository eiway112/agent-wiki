# 蒸馏卡模板（rule-template）

> 蒸馏出口（Memory/规范/Skill 三出口）的标准形态。
> 结构层由 validate.py 裁定（「适用边界」「来源指针」为必需章节且非空；「落地指针」字段与落地台账/目录一致性为维度 8/9，采用门控生效）；
> 语义层由判断层蒸馏回测裁定（人工或独立智能体，治具不覆盖）。

## 使用约定

- 文件名：`蒸馏卡_{topic}_{date}.md`，置于 `知识库/` 目录，并在 `目录.md` 建立引用；
- 🟢/🟡 落地必产卡；🔵 可不产卡（操作日志简述原因）；
- `落地指针` 声明本卡真实落地载体，供 validate.py 维度 8 核验「状态↔载体↔台账」一致：🟢 须指向存活载体（判定 ≥ WARM），🔵/无载体记 `none`；判定阶梯由弱到强 `INVALID<ORPHANED<NONE<WARM<HOT`，注入面不可达时降级为 `UNVERIFIED`（🟢 降 WARN）而非假 ERROR（详见 SKILL.md「记忆分层与注入面抽象」）；
- 蒸馏到 Memory 时，卡正文即 Memory 内容底稿，「适用边界」须随 Memory 正文一同写入；
- 蒸馏到规范/Skill 时，卡作为该规范段落或 Skill 条目的来源凭证。

## 卡格式

```markdown
# {规则名（一眼可读的行为断言）}

---
- 落地状态: {🟢 已落地 / 🟡 部分落地}
- 落地指针: {memory:<文件名> / file:<绝对路径>[#锚] / none；多指针以 ; 分隔}
- 落地去向: {Memory 标题 / 规范段落 / Skill 名}
- 蒸馏日期: {YYYY-MM-DD}
- 质量过滤器: 排他性 {✅/❌} | 生成力 {✅/❌}
---

## 来源指针
{原始采集文件相对链接 / 目录.md 条目 / URL；可追溯、可复采}

## 触发场景
{该规则在什么具体场景下被激活}

## 行为断言
{规则引入后智能体的决策如何不同；断言须可证伪}

## 适用边界
{前提条件 / 何时不适用；必填，不得为空。不声明边界的规则不值得信任}

## 回测记录
{Lint 抽样回测：日期 / 回测场景 / 结论；可初始为空，随回测追加}

## 认知结构扩展（可选区）
{心智模型 / 决策启发式层注记；认知结构蒸馏的预留接口，非必需，不预建管线}
```

## 设计说明

- **语义要求下沉为结构特征**：「适用边界」本是语义要求，下沉为必填章节后，零依赖治具即可裁定其存在性；写没写真话由判断层回测负责。裁定权按成本分层。
- **过滤器结果入卡**：`质量过滤器` 字段记录排他性/生成力两问的判定，使标记上限可追溯。
- **可选区克制**：「认知结构扩展」只留接口，不强制填写——命题知识蒸馏不需要它，避免为未发生的需求付税。
- **落地指针把载体与技能解耦**：技能本体不硬编码任何平台路径/用户名，真实载体由实例的 `注入面.json` 自描述。`落地指针` 让 🟢 状态可被治具对照真实载体机验，而非手抄断言；注入面不可达记 `UNVERIFIED`、无常驻注入能力封顶 `WARM`，是把真实能力边界诚实标注出来，而不是假装修复。
